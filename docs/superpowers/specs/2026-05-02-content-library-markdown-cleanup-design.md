# 中文产品资料库 Markdown 清理设计

日期：2026-05-02

## 背景

`docs/content-library` 已经从 `out/` 原始资料整理出产品资料和 Wiki 教程，并恢复了图片在正文中的相对位置。当前文档仍混有整理脚手架、来源追踪字段、自动生成描述、错误代码块、滥用引用块、残缺表格和缩进异常。这些内容会影响人工阅读、Obsidian 预览和后续网站 Wiki 模块接入。

本轮目标是把资料库正文整理为干净、稳定、可渲染的中文 Markdown。整理过程不重写原始内容，不重新标注图片，不删除原文中的外部链接、购买链接、QQ、激活码或教程链接。

## 范围

正文清理范围：

- `docs/content-library/products/*.md`
- `docs/content-library/wiki/*.md`

内部追踪归档范围：

- `docs/content-library/sources/`
- `docs/content-library/assets/**/_manifest.md`

不在本轮处理：

- 不重新生成图片文件名或图片描述。
- 不重新设计网站前端 Wiki 页面。
- 不清理原文中的敏感商业信息，只保留原位供后续发布审校。
- 不统一重写所有文章结构，只处理影响阅读和 Markdown 渲染的局部结构。

## 正文规则

每篇正文文档保留精简 YAML frontmatter，只允许以下字段：

- `title`
- `category`
- `product`
- `updated`

删除以下非正文脚手架：

- `source_docs`
- `assets_manifest`
- 标题下“本文档按原始资料的图文顺序重建...”类整理说明
- 文末“网站可用性与来源备注”
- 文末“来源文件”
- `描述已自动生成`
- `中度可信度描述已自动生成`
- `低可信度描述已自动生成`
- 其他只表达生成过程或可信度、但不表达产品或教程内容的残留文字

正文中的原始外部链接保留原位，包括视频、购买、网盘、语雀、QQ、激活码说明等。

## Markdown 格式规则

### 代码块

所有终端命令代码块使用 `bash`。误标为 `plain`、`text`、`c` 的命令块要改为 `bash`。

代码块只放可复制执行的命令。所有“命令 + 中文说明”都要拆开：

- 中文说明移到代码块外，放在命令前后。
- 命令单独放入 `bash` 代码块。
- 如果同一代码块里混有多个步骤，按原顺序整理为线性步骤。

例如：

````markdown
新手建议：

获取无人机定位数据，执行前记得检查定位数据是否正常输出。

```bash
./3DSLAM.sh
```

启动 egoplanner，使用 mid360 提供的障碍物点云信息。

```bash
roslaunch ego_planner single_run_in_expmid.launch
```
````

自然语言操作说明不放在代码块里，例如“解锁无人机”“按下 offboard 模式按键”“等待 rviz 打点飞行”“按 Ctrl+C 降落”等。

### 操作流程

多步骤教程优先整理成有序列表或连续小段落。每一步如果包含命令，就在该步骤附近放独立 `bash` 代码块。整理时保持原始步骤顺序，不把分散在不同章节的内容合并成统一模板。

### 引用块

引用块只用于真实引用。以下内容不使用 `>`：

- 产品配置清单
- 发货配套内容
- 服务说明
- 注意事项
- 重量、参数、购买说明
- 网盘分享说明

这些内容应转换为普通列表、段落或小标题下的线性说明。

### 表格

完整、可正常渲染的参数表可以保留。残缺表格不强行补表格结构，优先转换为线性 Markdown：

- 孤立 `|` 删除。
- 行尾错误竖线删除。
- 没有表头分隔线的图片说明表格转换为普通图片说明。
- 复杂、来源不清的表格残片转换为列表或普通段落。

### 图片和图片说明

图片必须保留在原始上下文位置附近，不移动到文末。图片说明紧跟图片，用普通文本呈现，不使用大段空格缩进。因缩进导致 Markdown 误渲染为代码块的图片说明要去掉缩进。

本轮不重新判断图片语义，不改用户后续准备手动标注的图片含义。

### 空行和标题

多余空行可适度收敛，保留阅读呼吸感。标题层级只修复明显错误，不为了统一模板重排整篇文章。中英文之间、命令和正文之间以可读性为准，不做大规模文案润色。

## 内部追踪归档

阅读区保持干净：

- `docs/content-library/products/` 只放产品正文。
- `docs/content-library/wiki/` 只放 Wiki 正文。
- `docs/content-library/assets/` 只放图片资源。

维护追踪材料移动到：

- `docs/content-library/internal/sources/`
- `docs/content-library/internal/manifests/...`

归档后 README 说明：

- 正文区用于阅读和后续网站内容参考。
- `internal/` 用于维护、来源追踪和资产核对。
- 读文档时不需要打开 `internal/`。

## 验证

实现后需要检查：

- 正文不再出现脚手架关键词：`描述已自动生成`、`可信度`、`网站可用性与来源备注`、`来源文件`、`source_docs`、`assets_manifest`、`本文档按原始资料`。
- 正文 frontmatter 只包含允许字段。
- 没有 `plain` 代码块。
- 没有把 shell 命令误标为 `c` 的代码块。
- 没有明显孤立竖线或残缺表格。
- 没有明显由缩进造成的误代码块。
- 所有本地图片引用仍然指向存在的图片文件。
- 抽样阅读改动最大的文档，确认图文顺序没有被大幅破坏。

## 成功标准

完成后，资料库正文应当像可维护的中文知识库，而不是生成过程记录。读者能顺畅阅读产品和教程内容，命令块能直接复制执行，图片仍出现在对应上下文中，内部来源追踪仍被保留但不污染阅读区。
